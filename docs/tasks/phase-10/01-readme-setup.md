# 10.1 — Write local setup and architecture overview

## Context

The public README must let a new developer understand and run the documented system.

## Objective

Create a source-grounded setup and architecture overview.

## Acceptance criteria

- [ ] Prerequisites, local startup, ports, and verification commands are correct.
- [ ] The README explains service ownership and why the project uses microservices.
- [ ] No credentials, tokens, or stale commands are included.

## Boundary and negative cases

- [ ] Setup instructions distinguish documented prerequisites from optional tooling.

## Out of scope

- Screenshots, cloud deployment, and marketing copy.

## Dependencies

- Completed infrastructure and service baseline.

## Expected tests

- Human walkthrough of commands; link/reference checks where configured.

## Definition of Done

Apply `docs/definition-of-done.md` with documentation-task exception as needed.

## Status and evidence

Use the status table from `docs/tasks/TEMPLATE.md`.
